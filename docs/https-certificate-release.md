# HTTPS 证书申请、续期与发版约定

生效：2026-10-03，用户明确要求。适用本仓库使用的、由我们管理的 HTTPS / WSS 域名，包括官网、API、管理后台、支付回调、自有下载与更新入口。

## 统一规则

- 后续新增和更换证书统一使用 **Let's Encrypt + ACME 自动申请、自动续期、自动部署**。不把需要人工每次申请、下载和替换的短期证书作为常规生产方案。
- 优先复用已验证的 Certbot 或 acme.sh。按客户端建议或 ARI 决定续期时机，定时任务至少每日检查；不得依赖固定“每三个月手动操作”或把证书有效期写死。
- 服务器端续期后必须自动将完整证书链部署到实际 TLS 终止点。Nginx 先校验配置再平滑 reload，保持现有请求和 WSS 连接；不能为了验证端口停业务或重启整台机器。
- TOS、OSS、CDN、负载均衡等托管入口还须自动上传新证书并更新对应域名的绑定。仅服务器本地续期成功、云证书中心上传成功、定时器存在，均不等于公网已使用新证书。
- 我们不能替换 Stripe、App Store、直播平台或云厂商默认域名的证书；这些第三方 HTTPS 入口校验信任链即可。客户端不内置服务器私钥，不关闭证书或主机名校验，不以 HTTP 替代失败的 HTTPS。

## 验证方式与权限

1. 自建 Web 网关优先使用不中断业务的 HTTP-01 webroot；确认公网 80 端口及 `/.well-known/acme-challenge/` 可达。挑战文件只用于验证，其他入口继续按既有 HTTPS 策略提供服务。
2. 通配符或不适合 HTTP-01 的域名使用有自动 API 的 DNS-01；人工添加 TXT 只能记作首次人工签发，不能标记自动续期完成。
3. 托管对象存储可使用自动 DNS-01，或通过 API 写入限定验证路径的 HTTP-01。保持稳定下载 CNAME 和品牌路径，不能在续期时来回切换业务 DNS。
4. 自动化使用专用最小权限身份，优先临时凭证/实例角色；权限限定到目标域名、验证记录/对象前缀和必要的证书部署 API。不得默认授予全账号管理员或复用另一产品的凭据。
5. 密钥和 ACME 账号材料只保存在受控私密目录或秘密管理系统；私钥文件至少 0600，目录 0700。仓库只记录路径、权限和引用，不保存 AK/SK、私钥正文、密码或请求签名；SDK 调试日志关闭。
6. 每组证书明确唯一续期负责人/执行主机与部署目标，避免多台机器重复申请、覆盖或触发频率限制。现网切换前保留有效旧证书、云证书 ID 和绑定回退信息。

## 发版前必须核验

- [ ] 域名、DNS/CAA、实际 TLS 终止点、证书 SAN、完整信任链和有效期一致。
- [ ] ACME 正式签发已成功；staging 演练及续期验证通过，staging 证书不会上传到生产绑定。
- [ ] systemd timer / cron 已启用，最近执行及下次执行时间可查；确认机器重启后仍会运行。
- [ ] deploy hook 覆盖全部实际入口；Nginx reload 或云端绑定成功，从服务器外部读回的新证书指纹/到期时间与目标一致。
- [ ] 官网、API、WSS、下载/更新文件及相应回调路由验证通过；同机其他产品保持原路由和证书。
- [ ] 失败重试、退出码、脱敏日志与通知渠道已配置并验证；监控同时检测续期失败和公网证书剩余时间，至少设置 14 天/7 天告警。没有接收人和验证记录不能勾选完成。
- [ ] 失败时保留有效旧绑定并通知，不静默宣布成功；保留可回退配置，禁止部署已过期或 staging 证书。

## 每次发版的证书回执

| 项目 | 必须登记的证据 |
| --- | --- |
| 域名 / 产品 / 地域 | 本次实际目标；不能抄用另一产品的服务器或桶 |
| 证书执行位置 | 主机、工具版本、证书名称、私密配置路径、续期负责人 |
| 验证与权限 | HTTP-01/DNS-01、专用身份和资源范围；不含凭据正文 |
| 自动任务 | timer/cron、最近/下次时间、续期演练结果 |
| 部署与读回 | deploy hook、云证书 ID/绑定、外部 TLS 指纹、SAN、到期时间 |
| 故障处理 | 告警接收人/渠道、验证时间、旧证书/配置回退位置 |
| 验收范围 | 文档/本地配置/签发/自动续期/部署/公网实测分别标记 |

本文件只建立后续发版要求，不表示本仓库全部历史域名已完成自动化。已有可用证书保持服务连续，在明确的证书维护窗口核验并接入上述流程；不得仅因本次文档同步执行 DNS 切换、业务迁移或批量换证。具体服务器和产品发布顺序仍以本仓库现有清单为准。
